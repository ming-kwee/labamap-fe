# API Reference — Channel JOLT Specs Admin

Base URL: `http://localhost:8888/labamap/api/v1/admin/channel-jolt-specs`

Manages `channel_jolt_specs` collection — category-aware JOLT transformation specs generated by APM and used by the publish pipeline.

**Status: Implemented** (2026-06-04)

**Files:**
- `adaptivepattern/controller/ChannelJoltSpecAdminController.java`
- `adaptivepattern/model/dto/ChannelJoltSpecUpdateRequest.java`
- `adaptivepattern/repository/ChannelJoltSpecRepository.java` — added `findByChannelId()` and `findByChannelIdAndCategoryId()`

## GET `/admin/channel-jolt-specs`

List specs with optional filters. Filter priority:
1. `channelId` + `categoryId` → specs for that pair
2. `channelId` only → all specs for that channel
3. none → all specs (use sparingly)

Additional filters applied reactively on top: `organizationId`, `isSystemDefault`, `isManuallyConfigured`, `isActive`.

Default: active-only. Pass `isActive=false` to include inactive specs.

**Query params:**

| Param | Type | Default | Description |
|---|---|---|---|
| `channelId` | String | — | Filter by channel |
| `categoryId` | String | — | Filter by category (use with channelId) |
| `organizationId` | String | — | Filter by org; omit for system defaults |
| `isSystemDefault` | Boolean | — | Filter system defaults only |
| `isManuallyConfigured` | Boolean | — | Filter manually curated specs |
| `isActive` | Boolean | `true` | Pass `false` to include inactive specs |

**Response:** `ChannelJoltSpec[]` (joltSpec content included)

## PUT `/admin/channel-jolt-specs/{id}`

Update a JOLT spec — edit content and optionally mark as manually configured to protect from future APM overwrite.

**Request body:**

```json
{
  "joltSpec": [
    {
      "operation": "shift",
      "spec": {
        "name":     "product.title",
        "price":    "product.variants[0].price",
        "sku":      "product.variants[0].sku",
        "material": "product.metafields[0].value",
        "color":    "product.options[0].values[0]"
      }
    }
  ],
  "markAsManuallyConfigured": true
}
```

When `markAsManuallyConfigured: true`, sets `joltMetadata.isManuallyConfigured = true`. APM will skip overwriting this spec on subsequent analyse calls (requires code change in `AdaptivePatternMatchingCommandImpl` — see below).

When `markAsManuallyConfigured: false`, re-opens the spec for APM auto-updates.

When `joltSpec` or `description` is `null`, the existing values are preserved.

**Immutable fields:** `channelId`, `categoryId`, `organizationId`, `isSystemDefault`, and all APM metadata (`confidence`, `strategyBreakdown`, `generatedAt`, `generatedBy`, `mappingCount`).

**Response:** `200 OK` — updated spec or `404`

---

## DELETE `/admin/channel-jolt-specs/{id}`

Delete a single spec. The next publish or analyse call for this `(channelId, categoryId, organizationId)` combination will regenerate a fresh spec via APM.

**Response:** `204 No Content`

---

## DELETE `/admin/channel-jolt-specs`

Bulk delete JOLT specs. Returns count of deleted documents.

**Query params:**

| Param | Required | Description |
|---|---|---|
| `channelId` | Yes | Channel to clear specs for |
| `categoryId` | No | If provided, clears only that category's specs |
| `organizationId` | No | If provided, clears only that org's specs |

**Combination behaviour:**

| channelId | categoryId | organizationId | Effect |
|---|---|---|---|
| amazon | — | — | All Amazon specs deleted |
| amazon | electronics | — | Only Amazon electronics specs deleted |
| shopify | — | org_123 | Only org_123's Shopify specs deleted |
| amazon | electronics | org_123 | Only org_123's Amazon electronics specs deleted |

**Response:** `200 OK`
```json
{ "deleted": 12, "channelId": "amazon", "categoryId": null, "organizationId": null }
```

## JOLT Spec Lifecycle

```
POST /channels/publish/analyze
        ↓
AdaptivePatternMatchingCommandImpl
        ↓
Check: existing spec in channel_jolt_specs?
  ├── Found + isManuallyConfigured=true  → use as-is, skip APM
  ├── Found + forceReanalyze=false       → use existing spec
  └── Not found OR forceReanalyze=true  → run APM, generate new spec, save
```

The `PUT /{id}` endpoint with `markAsManuallyConfigured: true` locks a spec at the top branch of this flow, preventing APM from ever overwriting it.

## Required Code Change in APM

For `isManuallyConfigured` protection to take effect, `AdaptivePatternMatchingCommandImpl.saveOrUpdateJoltSpec()` needs a guard (not yet implemented):

```java
.flatMap(existing -> {
    if (Boolean.TRUE.equals(
            existing.getJoltMetadata() != null
            ? existing.getJoltMetadata().getIsManuallyConfigured()
            : false)) {
        log.info("Skipping JOLT overwrite — manually configured: {}/{}/{}",
                channelId, categoryId, organizationId);
        return Mono.just(existing); // do not overwrite
    }
    // proceed with APM-generated overwrite
    ...
})
```

## Implementation Notes

**Controller:** `adaptivepattern/controller/ChannelJoltSpecAdminController.java`
**DTO:** `adaptivepattern/model/dto/ChannelJoltSpecUpdateRequest.java`
**Repository:** `adaptivepattern/repository/ChannelJoltSpecRepository.java`

Two methods were added to the repository:
- `findByChannelId(channelId)` — all specs for a channel regardless of isActive
- `findByChannelIdAndCategoryId(channelId, categoryId)` — all specs for channel+category pair

**No POST endpoint** — JOLT specs are created exclusively by `AdaptivePatternMatchingCommandImpl`. The admin API only reads, edits, and deletes existing specs.

**`isManuallyConfigured` protection requires a code change in APM** — see Required Code Change section above. Until that guard is added, `markAsManuallyConfigured=true` stores the flag but APM still overwrites the spec on the next analyse call.
